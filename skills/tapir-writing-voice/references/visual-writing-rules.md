# Tapir 文章插图规则

图片承担解释或举证任务，不能只用于装饰。

## 什么时候应该插图

- 文字需要较长篇幅才能解释清楚界面或结构；
- 需要证明项目确实运行、下单或失败；
- 需要比较参考与实现、旧版与新版、方案 A 与方案 B；
- 需要展示时间顺序、架构关系或操作流程；
- 一个视觉细节直接影响文章观点。

## 每张图要回答一个问题

- 它长什么样？
- 它真的运行了吗？
- 两个方案有什么差别？
- AI 具体做到了哪一步？
- 作者为什么会相信项目接近成功？
- 失败发生在什么位置？
- 哪个流程只靠文字不容易理解？

无法回答任何问题的图片可以删除。

## 图片优先级

1. 作者自己的实机照片和视频帧；
2. 项目过程截图、对比图和测试结果；
3. 订单、制造、报错和真实流程证据；
4. 为解释结构制作的简图；
5. 获得授权的外部参考图；
6. AI 生成的示意图。

AI 生成图只能用于示意，不能冒充项目实物或测试证据。

## 放置与图注

- 在文字第一次需要图片时就近放置；
- 先用一两句话告诉读者为什么要看；
- 图片下方提供简短图注；
- 图注指出读者应该看哪里，不重复正文；
- 连续图片较多时使用对比图、拼图或编号；
- 不要把所有图片堆在文章末尾。

推荐：

```text
图 3　AI 生成的 Cadenza PCB。界面已经很像正式工程，但底栏仍显示大量未布线项。
```

避免：

```text
图 3　梦想与现实的交界处。
```

## 隐私和版权

- 公开前检查用户名、订单号、物流、机器名和本地路径；
- 聊天截图只保留文章需要的内容；
- 外部作品标明作者和来源；
- 无法确认授权时优先使用链接和文字说明；
- 裁切不能改变证据原意。

## 交付检查

- 重要抽象概念是否需要图片；
- 每张图是否在正文中被解释；
- 图片是否支持附近的观点；
- 图注是否具体；
- 是否存在重复图片；
- 是否泄露隐私；
- 是否需要补充来源或授权。
