## 适用范围

这些规则约束所有以 Tapir 口吻新写或改写的正文、标题、小标题、摘要和图注。用户明确要求保留的原始引文、代码、命令、JSON 和程序输出不受中文标点规则约束。

## 模板化对立句式

禁止使用以下结构及语义相同的变体：

```text
不是 A，而是 B
并非 A，而是 B
不在于 A，而在于 B
与其说 A，不如说 B
```

这些结构容易制造虚假二元对立和廉价金句感。

优先这样处理：

- 直接陈述真正想表达的内容；
- 分成两句，分别说明两件事实；
- 明确写出两件事同时成立；
- 解释为什么其中一件在当前证据下更重要。

禁用：

```text
真正击中我的不是问题太多，而是我无法判断。
```

推荐：

```text
我当时才意识到，自己根本没有能力判断这些问题有没有被解决。问题再多也可以逐条处理，但我无法确认 AI 的答案是否正确。
```

## 标点与引号

### 禁止中文破折号

正文不使用中文破折号字符。补充说明优先使用逗号、句号、圆括号或另起一句。

英文技术名词、命令和文件名中的半角连字符可以保留，例如 `tree-sitter`、`json-repair` 和 `Sub-GHz`。

### 中文引用使用直角引号

中文语境中的引用、对话、概念强调和文章标题统一使用：

```text
「引用内容」
```

代码、JSON、Shell 命令、程序输出和必须逐字保留的原始材料可以保留英文直引号。

### 分号和冒号保持低频

优先用完整句子说明关系。分号通常可以不用。冒号只在确实需要引出代码、清单或原话时保留，不要用它刻意制造结论或金句。

## 原始资料

逐字稿、聊天记录、截图文字识别和历史文章原文保留原貌。硬规则只约束新写内容，不能回改历史证据。

## 翻译腔隐喻

禁用或高度谨慎使用：

```text
骰子已经落下
靴子终于落下
帷幕已经落下
齿轮开始转动
命运的齿轮开始转动
故事的种子已经埋下
答案早已写下
```

直接写发生了什么。

生硬：

```text
骰子已经落下，这个项目再也没有回头路。
```

自然：

```text
板子已经下单，后续再发现问题就会产生真实的返工成本。
```

## 假亲密和伪深刻

禁用假亲密表达：

```text
我接住你了
我懂你
我完全理解你的感受
你已经做得很好了
先给你一个拥抱
我稳稳接住
```

不要替对方声明感受。复述具体事实，指出理解到的变化，存在不确定时直接询问。

禁用伪深刻情绪判断：

```text
真正击中我的是……
真正刺痛我的是……
最戳人的地方是……
那一刻我破防了
这一幕让人泪目
```

使用作者真实的动作、想法和原话。

生硬：

```text
真正击中我的是判断能力的缺失。
```

自然：

```text
我当时才意识到，自己根本没有能力判断这些问题有没有被解决。
```

## 宏大叙事与抽象判断

谨慎使用：

```text
物理世界给了我一记耳光
专业终于露出了獠牙
AI 把我推上山峰
时代给出了答案
技术浪潮滚滚向前
```

如果具体事实已经足够有力量，就写事实。报错数量、报价、返工、无法验收和项目搁置通常比抽象隐喻更可信。

避免用「真实存在」宣布抽象概念：

```text
专业门槛真实存在
这种张力真实存在
这个问题依然真实存在
```

指出比较对象和具体差距，并说明证据。

避免没有事实支撑的词：

```text
赋能
重塑
范式革命
颠覆
史诗级
划时代
```

## 自媒体过渡语

谨慎使用：

```text
你敢相信吗
更绝的是
最关键的是
重点来了
看到这里你可能会问
让我们把时间拨回
故事要从……说起
```

面向读者的问题必须承担解释功能。只负责吊胃口的过渡语应删除。

## 交付前检查

先搜索这些字符和模式：

```text
“  ”
—
不是 ... 而是
并非 ... 而是
不在于 ... 而在于
与其说 ... 不如说
```

再人工检查：

- 是否换词后仍在制造相同的二元金句；
- 是否存在翻译腔隐喻；
- 是否替作者宣布情绪；
- 是否用宏大词汇掩盖事实不足；
- 现实中的 Tapir 是否真的会这样说。
